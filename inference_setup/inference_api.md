
# Inference API

Our inference server uses `llama.cpp` to serve Qwen3-1.7B through an OpenAI-compatible API.

This guide covers two types of requests:
1. **Basic inference:** Ask the model a question and receive a response.
2. **Tool calling:** Let the model request execution of a predefined function.

## 1. Server Connection

Start the server from the project root:

```bash
./inference_setup/start_server.sh
```

The server listens at:

```text
http://127.0.0.1:8080
```

Both types of inference use:

```text
POST /v1/chat/completions
```

The examples below use Python's `requests` library:

```bash
uv pip install requests
```

The examples assume Python is running on the EC2 instance, or on a computer connected through an SSH tunnel.

## 2. Important Request Parameters

| Parameter | Type | Description |
|---|---|---|
| `messages` | list | **Required.** Conversation messages containing a `role` and `content`. |
| `max_tokens` | int | Maximum number of tokens generated, including reasoning tokens. Affects generation length and potentially latency. |
| `temperature` | float | Controls randomness. Use `0` for more deterministic results. |
| `tools` | list | Defines the functions that the model may request. Used for tool calling. |
| `tool_choice` | string | Controls whether the model uses a tool: `"auto"`, `"required"`, or `"none"`. |

### Message roles

- `system`: Instructions defining the model's behavior.
- `user`: A user question or request.
- `assistant`: A response previously generated by the model.
- `tool`: The result returned after executing a tool.

For basic inference, you normally only need `messages`, `max_tokens`, and optionally `temperature`.

For tool calling, additionally provide `tools` and `tool_choice`.

## 3. Basic Inference

Send a question to the model and retrieve its text response.

```python
import requests

URL = "http://127.0.0.1:8080/v1/chat/completions"

payload = {
    "messages": [
        {
            "role": "user",
            "content": "What is machine learning?"
        }
    ],
    "max_tokens": 200,
    "temperature": 0
}

response = requests.post(URL, json=payload, timeout=120)
response.raise_for_status()

data = response.json()
print(data["choices"][0]["message"]["content"])
```

The model returns a response in:

```python
data["choices"][0]["message"]["content"]
```

`max_tokens` limits the generated tokens, while `temperature` determines the sampling behavior.

## 4. Tool Calling

Tool calling allows the model to decide which function to invoke and generate its arguments.

**The model does not execute the function itself.** The application must execute the requested function and optionally return the result to the model.

### Step 1: Define a tool

Here we define a simple function for adding two integers.

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "add",
            "description": "Add two integers.",
            "parameters": {
                "type": "object",
                "properties": {
                    "a": {
                        "type": "integer",
                        "description": "First integer"
                    },
                    "b": {
                        "type": "integer",
                        "description": "Second integer"
                    }
                },
                "required": ["a", "b"]
            }
        }
    }
]
```

Important fields:

- `name`: The function the model can request.
- `description`: Helps the model determine when to use it.
- `parameters`: JSON Schema describing the function arguments.
- `required`: Arguments that must be provided.

### Step 2: Request a tool call

```python
import json
import requests

URL = "http://127.0.0.1:8080/v1/chat/completions"

messages = [
    {
        "role": "user",
        "content": "Use the add tool to calculate 17 + 25."
    }
]

payload = {
    "messages": messages,
    "tools": tools,
    "tool_choice": "required",
    "max_tokens": 200,
    "temperature": 0
}

response = requests.post(URL, json=payload, timeout=120)
response.raise_for_status()

data = response.json()
message = data["choices"][0]["message"]

print(json.dumps(message.get("tool_calls", []), indent=2))
```

A tool call may look like:

```json
[
    {
        "id": "call_123",
        "type": "function",
        "function": {
            "name": "add",
            "arguments": "{\"a\":17,\"b\":25}"
        }
    }
]
```

The `arguments` field is a JSON-encoded string, so it must be parsed before use.

**`tool_choice` options:**

- `"required"`: Force the model to request a tool. Useful for testing.
- `"auto"`: Let the model decide whether to use a tool.
- `"none"`: Disable tool calling for that request.

### Step 3: Execute the tool

```python
def add(a, b):
    return a + b

tool_calls = message.get("tool_calls", [])

if not tool_calls:
    raise RuntimeError("Model did not return a tool call")

tool_call = tool_calls[0]

if tool_call["function"]["name"] != "add":
    raise ValueError("Unexpected tool")

arguments = json.loads(tool_call["function"]["arguments"])

if (
    type(arguments.get("a")) is not int
    or type(arguments.get("b")) is not int
):
    raise ValueError("Invalid tool arguments")

result = add(arguments["a"], arguments["b"])
print("Tool result:", result)
```

Expected result:

```text
Tool result: 42
```

### Step 4: Return the tool result to the model

To let the model generate a final response using the tool result, append the assistant's tool call and the tool's output to the conversation.

```python
messages.append(message)

messages.append({
    "role": "tool",
    "tool_call_id": tool_call["id"],
    "content": str(result)
})

response = requests.post(
    URL,
    json={
        "messages": messages,
        "max_tokens": 200,
        "temperature": 0
    },
    timeout=120
)

response.raise_for_status()

final_message = response.json()["choices"][0]["message"]
print(final_message["content"])
```

The final answer should indicate that 17 + 25 = 42.

## 5. Important Notes

- Both basic inference and tool calling use `/v1/chat/completions`.
- Tool calling requires `--jinja` to be enabled in our `llama-server` configuration.
- The model generates tool requests, but the application is responsible for executing tools and validating their arguments.
- Use `tool_choice="required"` to test tool-calling support. Use `"auto"` when you want the model to decide whether a tool is necessary.
- `max_tokens` is a maximum, not a guarantee that the model will generate that many tokens.
- Qwen3 may generate reasoning tokens, which count toward the output token limit. If the response is truncated, increase `max_tokens`.
- The server currently binds to `127.0.0.1`, so it is not directly accessible from other machines.

For local access from your computer, establish an SSH tunnel:

```bash
ssh -N -L 8080:127.0.0.1:8080 cse291a
```

Then send requests to `http://127.0.0.1:8080` as usual.
